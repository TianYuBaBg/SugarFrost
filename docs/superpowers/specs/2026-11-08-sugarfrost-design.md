# SugarFrost 设计文档

- 日期：2026-11-08
- 目标形态：微信小游戏（同时保留浏览器调试入口）
- 参考实现：`minigame-everyday/day-04-sheep`（《羊了个羊：星球》核心玩法复刻）

## 1. 目标与范围

做一款竖屏单人「三消堆叠」小游戏：牌堆中 108 张糖霜卡互相遮挡，点开未被遮挡的卡放进主槽，
槽内同类型自动聚合，连续 3 张同类消除；槽满 7 张未消判负，牌堆清空判胜。

**范围内**

- 108 张卡（12 类 × 9 张）、主槽 7 格、5% 遮挡阈值、三消消除、胜负判定、点击重开
- 全程序化矢量美术（无任何图片资源），糖霜/糖果主题
- 微信小游戏入口 + 浏览器调试入口，基础微信能力（竖屏、屏幕常亮、分享）

**范围外**

- 登录 / 云开发排行榜 / 激励视频广告
- 音效、多关卡、道具（洗牌、撤销、移出 3 张）
- 关卡可解性保证（与参考实现一致：纯随机，接受死局）

**规则口径：与 day-04-sheep 100% 同款，只换主题皮肤。**

## 2. 架构

玩法逻辑沿用 day-04 的已验证实现，美术层独立成模块，二者只通过数据交互。

```
SugarFrost/
├── game.js / game.json / project.config.json   # 微信小游戏入口
├── index.html                                   # 浏览器调试入口
├── package.json                                 # "type": "module"（供 node 自测）
├── js/
│   ├── main.js                 # Phaser 启动 + DPR/视口
│   ├── libs/                   # phaser.min.js / weapp-phaser3-adapter.min.js / symbol.js
│   ├── core/config.js          # 12 种糖定义、尺寸、阈值、动画时长、堆叠参数
│   ├── core/LevelGenerator.js  # 6 摞×10 + 48 散卡
│   ├── core/rules.js           # 纯函数：相交/并集面积/插入位/三连检测
│   ├── core/platform.js        # wx / 浏览器差异封装
│   ├── art/palette.js          # 糖霜色板
│   ├── art/CardArt.js          # 卡面烘焙（12 种糖果图形）
│   ├── art/SlotArt.js          # 木托盘 + 7 凹槽烘焙
│   ├── art/Background.js       # 渐变背景 + 霜花烘焙
│   └── scene/GameScene.js      # 编排：状态机 / 交互 / tween / 胜负
└── tools/selftest.mjs          # 无头自测
```

**为什么拆 `rules.js`**：遮挡并集面积、插入位、三连检测都是纯函数，可以脱离 Phaser 在 node 里
跑对拍测试；`GameScene` 只负责把纯函数的结论落到 sprite 与 tween 上。

## 3. 关卡生成（1:1 复刻）

- 类型池：12 类 × 9 张 = 108 张，全池洗牌后顺序取用（每摞类型随机，避免整摞同色）。
- 牌堆区：`x ∈ [30, 690]`、`y ∈ [260, 1080]`（`HUD_HEIGHT 230 + 30` 到 `1280 - 160 - 40`）。
- 6 摞，每摞 10 张；摞内第 i 张相对底牌偏移 `(i*2.5, i*-3.5)`，整摞再旋转 ±10°；
  每摞 `zStart = rand[0, maxZ-PILE_HEIGHT]`，`maxZ = 10 + 8 + 4 = 22`。
- 剩余 48 张散卡：位置在区域内按 `SCATTER_JITTER 0.92` 抖动，`z = rand[0, 21]`。
- 摞心用 3×2 网格 + ±15px 抖动生成，打乱后分配给各摞。

## 4. 遮挡判定（1:1 行为 + 增量重算）

- 两卡 AABB 求交集，对某卡所有「上层」交集矩形求**并集面积**（坐标压缩网格法），
  `< 0.05 × 76 × 76` 即解锁。
- 「上层」= 绘制序 `(zLayer, id)` 字典序，同 z 内 id 大者在上（`isAbove`）。
- **增量**：一次动作只重算「与被移走卡片相交的存活卡片」的遮挡（dirty 集合），
  不再全量 N²。`tools/selftest.mjs` 用全量结果与之对拍，保证行为等价。

## 5. 槽位与三消（1:1）

- 槽底逻辑宽 `720 × 0.92 = 662.4`，高 `= 宽 / (2000/556) = 184.19`，底距 24 → 中心 y。
- 7 个凹槽中心由 `LEFT_CX 0.1583 / RIGHT_CX 0.8460` 线性插值，步距 75.9。
- 插入位：槽内最后一张同类型的下标 K → 插到 K+1，其后全部右移。
- 动画：飞入 280ms `Cubic.easeOut`，右移 180ms，三消缩小淡出 220ms，压缩左移 220ms。
- 判定：入槽并处理完三消后，牌堆无牌 → 胜；`slot.length >= 7` → 负。
- 全局动画锁 `isAnimating` 期间忽略点击。

## 6. 视觉（糖霜主题，全程序化）

所有美术在启动时用 `Phaser.Graphics` 绘制一次并 `generateTexture()` 烘焙成贴图，
之后场景里只用 `Image`，保证 Canvas / WebGL 双渲染器一致、每帧开销恒定。

- **背景**：竖直三段式渐变（分层色带模拟）+ 24 个半透明六角霜花 + 顶部柔光。
- **卡面**（76×76，圆角 16）：深色厚底（下移 3px 模拟厚度）→ 糖果主色本体 →
  4 层内缩圆角矩形模拟糖霜白边 → 左上高光弧 → 底部深色描边。
  遮挡态：一层 `0x5B6B7C` 42% 透明圆角罩（不用 `setTint`，避免 Canvas tint 开销）。
- **12 种糖**：甜甜圈 / 棒棒糖 / 马卡龙 / 纸杯蛋糕 / 冰淇淋筒 / 拐杖糖 / 小熊软糖 /
  曲奇 / 棉花糖 / 巧克力块 / 果冻豆 / 冰棒，各一个绘制函数 + 专属配色。
- **卡槽**：木托盘 `#C98B5E` 底 + 木纹线 + 7 个内凹圆角格（`#8B5A33` 描边 / `#E3C7A8` 内底）。
- **HUD**：标题「糖霜消消」白字糖浆描边，状态行 `牌堆 96/108 · 槽 3/7`。
- **胜负浮层**：半透黑 + 大标题 + 「点屏幕重开」。

标题沿用「糖霜消消」，卡槽做木托盘质感（与糖果卡面的暖色统一）。

## 7. 平台适配

- `DPR = clamp(devicePixelRatio, 1, 3)`；画布 = CSS×DPR；宽高比超过 `720:1280` 时按高度收窄居中。
- `type: Phaser.CANVAS`（微信小游戏沙盒要求），`scale.mode NONE`、`zoom = 1/DPR`。
- 逻辑坐标统一 720×1280；`uiScale = WIDTH / 720`，`offsetY` 竖直居中。
- `platform.js`：`getViewport()` 优先 `wx.getSystemInfoSync()`；`keepScreenOn()` 调
  `wx.setKeepScreenOn`；`setupShare()` 调 `wx.showShareMenu` 并注册 `onShareAppMessage`；
  浏览器端全部 no-op。

## 8. 验收标准

1. `npx http-server SugarFrost` 打开 `index.html`：108 张正常堆叠、糖霜质感卡面、可点/遮挡区分明确。
2. 依次点完 108 张 → 通关浮层；故意塞满 7 格 → 失败浮层；点屏幕重开重新随机。
3. `node tools/selftest.mjs`：100 局张数/类型分布正确、增量遮挡与全量对拍一致、插入位与三连断言通过。
4. 微信开发者工具导入目录后可运行（需人工在工具内验证）。
5. 无 console error；`buildCards` 耗时 < 100ms。

## 9. 风险

- `generateTexture` 在微信 Canvas 渲染器下依赖适配器的离屏 canvas；若失败，卡面会空白。
  缓解：烘焙后校验 `scene.textures.exists(key)`，缺失时回退到直接 Graphics 绘制。
- 108 个 `Image` + 1 个大背景贴图在低端机上内存约 3–5 MB，可接受；
  若超限可把卡面烘焙分辨率降到 1.0× 逻辑像素。
